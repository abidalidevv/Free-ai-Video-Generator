1. Project Overview

VideoForge AI is an enterprise-grade AI video production suite designed to automate short-form (9:16 Shorts/TikTok/Reels) and widescreen (16:9) video creation. VideoForge serves as the user interface, integration layer, task scheduler, and asset management workstation.

Prompt-to-Video Synthesis

Full AI script generation, automatic scene-by-scene keyword extraction, and dynamic video synthesis via MPT upstream.

Orderly Serial Batch Queue

Autonomous batch rendering queue orchestrator with strict MAX_CONCURRENCY = 1 enforcement for Windows MoviePy tempfile safety.

Dual-Source Output Vault

Persistent output library reconciling live MPT background tasks with local browser storage, ensuring renders survive backend restarts.

2. Architecture & Data Flow

Single Source of Truth: MoneyPrinterTurbo is the authoritative engine. VideoForge AI never executes local video rendering, never generates fake task states, and never fakes token statistics.

8. Rendering Pipeline Execution

When a render is submitted from VideoForge to MPT via POST /api/v1/videos, the upstream engine executes the following discrete linear stages:

  1. Audio Synthesis: Edge-TTS generates spoken audio narrative from the script text. Audio duration is computed to calculate target video duration.
  2. Subtitle Sub-Assembly: Whisper or MoviePy TextClips parse timestamps and render subtitle cards with user-defined stroke widths, font families, and colors.
  3. Footage Acquisition: B-roll video clips matching the generated visual keywords are downloaded from Pexels/Pixabay or retrieved from local storage.
  4. Composite Assembly: MoviePy clips together video fragments, applies transitions, ducks background music under spoken narrative, and superimposes subtitles.
  5. H.264 Muxing: FFmpeg encodes final MP4 to storage/tasks/{task_id}/final-1.mp4. Task transitions to state = 1.

9. Queue & Windows Concurrency Architecture

CRITICAL ARCHITECTURAL CONSTRAINT: MAX_CONCURRENCY = 1
On Windows operating systems, concurrent rendering causes MoviePy to collide on a hardcoded temporary audio file: final-1TEMP_MPY_wvf_snd.mp4. VideoForge AI strictly enforces maxConcurrency = 1 in useQueueOrchestrator to guarantee 100% video integrity and prevent WinError 32 file-locking crashes.

The queue runner processes jobs sequentially:

  • Job 1 dispatched via POST /api/v1/videos -> status set to rendering.
  • Job 2 remains in status queued.
  • Job 1 finishes (`state = 1`) -> saved to videoforge_outputs_v1 -> status set to completed.
  • Job 2 is automatically picked up by useQueueOrchestrator and dispatched to MPT.

10. Audio & BGM Timeline Engine

VideoForge AI connects directly to MPT audio endpoints:

  • Edge-TTS: Free, high-fidelity neural voice synthesis without API keys (e.g. en-US-GuyNeural-Male, en-US-AriaNeural-Female).
  • Background Music (BGM): Retrieved dynamically from MPT's resource/songs catalog via GET /api/v1/musics.
  • Custom BGM Upload: Uploads MP3/WAV audio via POST /api/v1/musics, automatically selecting the uploaded track.
  • Volume & Ducking: BGM volume is configurable from 0% to 100% (default: 20%) and automatically ducked beneath the primary voice narrative.

11. Assets Library & Local Materials

VideoForge AI supports local video footage clips:

  • Inspects clips via GET /api/v1/video_materials.
  • Accepts multi-part uploads up to 200MB via POST /api/v1/video_materials.
  • Supports selecting local materials in Video Settings (`/video-settings`), enabling synthesis exclusively from user-provided footage rather than stock downloads.

12. Outputs & Video Streaming

Rendered videos are streamed and downloaded directly from MPT storage:

  • H.264 MP4 Streaming: Served via GET /api/v1/stream/{task_id}/final-1.mp4. Uses HTTP byte-range requests (Accept-Ranges: bytes), enabling HTML5 video scrubbing.
  • Direct Attachment Download: Served via GET /api/v1/download/{task_id}/final-1.mp4. Returns Content-Disposition: attachment; filename="final-1.mp4".
  • Metadata Drawer: Displays resolution, duration, file size, server engine version, creation date, and task UUID.

13. State Management & Persistence

VideoForge AI implements a robust dual-layer persistence strategy:

  • In-Memory (FastAPI): MPT stores active tasks in RAM during execution.
  • Client LocalStorage: Key videoforge_outputs_v1 persists completed outputs, and videoforge_projects_v1 persists draft scripts.
  • Survives Backend Restarts: If MPT is restarted, VideoForge automatically recovers previous outputs from localStorage, allowing continuous streaming and downloading as long as files remain on disk.

14. Security & Hardening

  • No Frontend Secrets: API keys (OpenAI, Pexels) are stored strictly in server-side config.toml and never exposed over HTTP.
  • Masked Environment Variables: Client-side keys in Developer Mode (`/developer`) are masked by default (`•••••••••••••`).
  • Strict Upload Constraints: Video uploads are capped at 200MB, images at 20MB, and audio at 50MB with file extension validation.

17. Known Limitations

  • Windows Concurrency Limit (MAX_CONCURRENCY = 1): Caused by MoviePy v1.0.3 temporary audio waveform collision (final-1TEMP_MPY_wvf_snd.mp4). Enforced in serial queue.
  • In-Memory Task Loss on MPT Restart: Upstream MPT stores task metadata in RAM. Mitigated by VideoForge's localStorage output persistence.
  • Provider Rate Limits (HTTP 429): External providers (Pexels, OpenAI) may rate-limit high-frequency requests on free tiers.

18. Unsupported MPT Capabilities

  • Active Task Cancellation: MPT returns HTTP 409 Conflict if attempting to delete an active render task. Tasks cannot be aborted mid-render.
  • Asset Rename / Delete: MPT provides read and upload for video materials, but no DELETE or PATCH endpoint.
  • Hardware GPU Telemetry & Token Counters: MPT does not expose GPU sensors or token billing meters over REST.
  • WebSocket Streaming: MPT is exclusively a REST API; real-time task progress is monitored via HTTP polling.
